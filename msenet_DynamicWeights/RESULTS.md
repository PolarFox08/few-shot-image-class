# Experimental Results: Task-Adaptive Dynamic Stage Weighting

This document presents the complete empirical evaluation of the **Task-Adaptive Dynamic Stage Weighting** novelty across the three prototypical distance metrics (**Euclidean**, **Cosine**, and **Hybrid**) on the **MiniImageNet** benchmark (5-way 5-shot evaluation over 600 episodes, ResNet-18 backbone).

---

## 1. Executive Summary: 3-Way Prototype Distance Comparison

All three models were trained under identical conditions from a shared ResNet-18 initialization with fixed attention scaling parameters ($\gamma_1 = \gamma_2 = 0.2$) and identical data splits (360 train episodes/epoch, 600 validation tasks/epoch, 600 test tasks).

| Distance Metric | Dynamic Weights | Final Test Accuracy (%) | 95% Confidence Interval (%) | Test Loss | Best Validation Accuracy (%) | Inference Time / Episode | Peak GPU VRAM | Total Parameters |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Cosine** | **Yes** | **83.50%** | **[83.00%, 84.00%]** | **0.4519** | **83.86%** | **89.62 ms** | 0.368 GB | 11,618,587 |
| **Hybrid** | **Yes** | **83.13%** | [82.60%, 83.65%] | 0.4624 | 83.70% | 93.76 ms | 0.458 GB | 11,618,587 |
| **Euclidean** | **Yes** | **82.57%** | [82.05%, 83.09%] | 0.4754 | 83.38% | **89.29 ms** | **0.280 GB** | 11,618,587 |

*Reference Baselines on MiniImageNet (5-way 5-shot):*
- **Original MSENet Baseline (Static Euclidean):** ~82.24% – 82.48%
- **Static Cosine MSENet ([`msenet_cosine`](../msenet_cosine/RESULTS.md)):** 82.97%
- **Cosine + Dynamic Weights (Ours):** **83.50%** (**+1.26 pp** over paper baseline, **+0.53 pp** over static cosine)

## 2. Paired Episode-Level Statistical Comparison

Because all three models were evaluated on the **exact same 600 test episodes**, we conduct paired head-to-head episode analyses to eliminate sampling variance:

| Comparison | Mean Acc Difference (pp) | 95% Confidence Interval (pp) | Std Difference (pp) | Total Episodes | Wins (%) | Ties (%) | Losses (%) |
|:---|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| **Cosine vs. Euclidean** | **+0.927 pp** | **[+0.634 pp, +1.220 pp]** | 3.661 pp | 600 | **52.5%** (315) | 14.7% (88) | 32.8% (197) |
| **Hybrid vs. Euclidean** | **+0.558 pp** | **[+0.339 pp, +0.777 pp]** | 2.734 pp | 600 | **46.5%** (279) | 21.2% (127) | 32.3% (194) |
| **Hybrid vs. Cosine** | **-0.369 pp** | **[-0.657 pp, -0.080 pp]** | 3.606 pp | 600 | 38.5% (231) | 14.7% (88) | **46.8%** (281) |

### Key Statistical Takeaway
- The 95% confidence intervals for both `Cosine - Euclidean` ($[+0.63, +1.22]$ pp) and `Hybrid - Euclidean` ($[+0.34, +0.78]$ pp) **strictly exclude zero**, confirming that replacing Euclidean distance with Cosine or Hybrid distance in dynamic stage weighting yields **statistically significant improvements**.
- Cosine distance outperforms Euclidean distance in more than **half of all test episodes (52.5%)**, with an episode win-to-loss ratio of **1.60 : 1**.

## 3. Dynamic Stage Weight Allocations

The table below reports the mean and standard deviation of the effective dynamic stage weights generated by the `TaskAdaptiveWeightGenerator` across all 600 test episodes:

| Distance Metric | Stage Name | ResNet-18 Module | Channels | Mean Dynamic Weight | Std Across Episodes | Weight Share (%) |
|:---|:---|:---|:---:|:---:|:---:|:---:|
| **Euclidean** | `stage_0` | `maxpool` | 64 | 0.1906 | 0.0008 | 8.5% |
| | `stage_1` | `layer1` | 64 | 0.2103 | 0.0003 | 9.3% |
| | `stage_2` | `layer2` | 128 | 0.1987 | 0.0006 | 8.8% |
| | `stage_3` | `layer3` | 256 | 0.5815 | 0.0101 | 25.9% |
| | `stage_4` | `layer4` | 512 | **1.0679** | 0.0184 | **47.5%** |
| **Cosine** | `stage_0` | `maxpool` | 64 | 0.2772 | 0.0043 | 6.0% |
| | `stage_1` | `layer1` | 64 | 0.2831 | 0.0005 | 6.2% |
| | `stage_2` | `layer2` | 128 | 0.2745 | 0.0013 | 6.0% |
| | `stage_3` | `layer3` | 256 | 0.2928 | 0.0090 | 6.4% |
| | `stage_4` | `layer4` | 512 | **3.4571** | 0.0213 | **75.4%** |
| **Hybrid** | `stage_0` | `maxpool` | 64 | 0.2137 | 0.0012 | 8.5% |
| | `stage_1` | `layer1` | 64 | 0.2233 | 0.0004 | 8.9% |
| | `stage_2` | `layer2` | 128 | 0.2156 | 0.0009 | 8.6% |
| | `stage_3` | `layer3` | 256 | 0.4366 | 0.0622 | 17.3% |
| | `stage_4` | `layer4` | 512 | **1.4355** | 0.1155 | **56.8%** |

### Stage Allocation Insights
1. **Dominance of Deep Features:** Across all metrics, `layer4` receives the largest weight ($47.5\%$ for Euclidean, $56.8\%$ for Hybrid, and $75.4\%$ for Cosine), corroborating the paper's core hypothesis that semantic abstractions govern class identity.
2. **Cosine Hyper-Focus:** Under Cosine distance, the model heavily amplifies Stage 4 ($3.4571$), while distributing balanced baseline weights ($0.27 - 0.29$) across stages 0–3. Because cosine features are unit-normalized, the gating network discovers that Stage 4 directional alignment provides extraordinarily clean class separation.
3. **Adaptive Responsiveness:** Under Hybrid distance, Stage 3 and Stage 4 exhibit substantial episode-to-episode variance ($\text{std} = 0.062$ and $0.116$), demonstrating that the gating network actively re-weights intermediate representations depending on task difficulty.

## 5. Computational Efficiency & Hardware Profiling

All metrics were benchmarked on a single **NVIDIA Tesla T4 GPU (16 GB)** using PyTorch AMP:

| Metric | Inference Time / Episode | Full Test Time (600 Tasks) | Throughput (Tasks/sec) | Peak GPU VRAM | Parameter Overhead |
|:---|:---:|:---:|:---:|:---:|:---:|
| **Euclidean** | 89.29 ms | 53.57 s | 11.20 tasks/s | 0.280 GB | +467 params (+0.004%) |
| **Cosine** | 89.62 ms | 53.77 s | 11.16 tasks/s | 0.368 GB | +467 params (+0.004%) |
| **Hybrid** | 93.76 ms | 56.26 s | 10.66 tasks/s | 0.458 GB | +467 params (+0.004%) |

- **Latency:** These runs only include dynamic-weighting models (no static run under the same timing setup), so the module's latency overhead is not isolated here. See the Stacked-DW results for a like-for-like timing (D0 DW-only: 37.1 ms/episode vs. 32--33 ms/episode for static baselines in other studies; different runs, so only indicative).
- **Ultra-Compact Footprint:** Peak memory usage remains strictly below **0.5 GB** during full 5-way 5-shot testing (with 15 query images per class, totaling 75 queries per task).
